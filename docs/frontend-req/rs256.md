# RS256 Key Setup and Usage

This document explains how to generate an RSA key pair for RS256 signing, where to place the keys for the backend, and how to provide the public key to frontend teams.

1. Generate an RSA key pair (2048-bit recommended):

```bash
openssl genpkey -algorithm RSA -out private_key.pem -pkeyopt rsa_keygen_bits:2048
openssl rsa -in private_key.pem -pubout -out public_key.pem
```

2. Place the keys in the backend project (development only):

- `src/main/resources/keys/private_key.pem` (private key; DO NOT commit real production private keys)
- `src/main/resources/keys/public_key.pem` (public key) — this file *is safe* to share with frontends

3. Configure the application (development):

In `application.yml` or environment variables set:

```yaml
jwt:
  use-rs256: true
  rsa:
    public-key-path: classpath:keys/public_key.pem
    private-key-path: classpath:keys/private_key.pem
```

4. Frontend usage

- The frontend does not need the private key — only the public key if it wants to verify tokens locally (rare).
- Instead, frontends should accept JWTs from the backend and validate signature server-side where necessary.
- If your frontend performs offline token verification (e.g., for local testing), use the `public_key.pem` and JWT libraries that support RS256 verification.

5. Production notes

- Do NOT commit production private keys to the repo. Use a secrets manager (Vault, AWS Secrets Manager, Azure Key Vault).
- Rotate keys periodically and publish new public keys to clients via a key rotation endpoint or a configuration push.
- Consider publishing a JWKS endpoint (`/.well-known/jwks.json`) for public key discovery.
